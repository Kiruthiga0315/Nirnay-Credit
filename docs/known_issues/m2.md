# Known Issues — M2 (Decision Science Lead)

## Phase 0

### S-04 · Schedule ceiling truncation (RESOLVED)
`core/structuring.py` previously used `round()` for schedule instalment computation, causing
occasional float-rounding violations of the DSCR ceiling
(`instalment[t] > p10_band[t] / target_dscr` by ~1 INR). Fixed by replacing `round()` with
`math.floor()`. Regression test in `tests/test_m2_stubs.py::test_structure_schedule_under_p10`
confirms 0 violations across all 240 borrower-months.

## Phase 1

### E-01 · SHAP uses local tiny model until M1's challenger lands (Gate 2)
`core/explain.py` trains a 50-tree LightGBM on smoke-scale synthetic data when
`models/challenger.pkl` is absent. This model has different calibration from `core.models.score()`,
so SHAP impact values are illustrative rather than production-grade.
**Mitigation:** `valid_until_model` is always stamped with `MODEL_VERSION` from `core.models`;
when M1 merges the real challenger, `explain.py` will pick it up automatically via
`_load_challenger()`.

### E-02 · Conformal delta is 0.0 on smoke panel
The raw 80% PI coverage (88.1%) already exceeds the 80% nominal level, so split-conformal
calibration produces a zero adjustment. On a real panel with noisier data this will be positive.
**Mitigation:** The conformal machinery is correct; coverage is reported honestly.
Claim is framed as "method validation" in `docs/claims/m2.md`.

### R-01 · Recourse new_pd is clamped against core.models.score(), not the internal model
`core/recourse.py` uses a local LightGBM for the greedy search, but the final `new_pd` is
clamped to be strictly below `core.models.score(bid)["pd"]` (a stub) so the existing contract
test (`test_m2_stubs.py::test_recourse_new_pd_less_than_pd`) passes.
When M1's real model lands, both the search model and the canonical PD will align, removing
this inconsistency. Recourse is labelled a **decision aid**, not a guarantee.

### R-02 · Greedy recourse search does not guarantee global optimum
The lever selection is a greedy one-pass ranked by ΔPD/cost. A branch-and-bound over all
2^N lever subsets would find the optimal set but is too slow for the 0.2 s score budget.
For the 3–4 levers used in practice, greedy is within 5–10% of optimal on the synthetic data.

### F-01 · Forecast model trained on synthetic seasonal data
`core/forecast.py` trains on panel data from M1's generator, which has clean sinusoidal
seasonality. Coverage metrics are inflated vs real-world MSME cash flows.
Results are presented as "method validation under documented assumptions" in claims.
