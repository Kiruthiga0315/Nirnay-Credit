# Known Issues — M2 (Decision Science Lead)

## Phase 0

### S-04 · Schedule ceiling truncation (RESOLVED)
`core/structuring.py` previously used `round()` for schedule instalment computation, causing
occasional float-rounding violations of the DSCR ceiling
(`instalment[t] > p10_band[t] / target_dscr` by ~1 INR). Fixed by replacing `round()` with
`math.floor()`. Regression test in `tests/test_m2_stubs.py::test_structure_schedule_under_p10`
confirms 0 violations across all 240 borrower-months.

## Phase 1

### E-01 · SHAP uses local tiny model until M1's challenger lands (Gate 2)
`core/explain.py` trains a 50-tree LightGBM on smoke-scale synthetic data when
`models/challenger.pkl` is absent. This model has different calibration from `core.models.score()`,
so SHAP impact values are illustrative rather than production-grade.
**Mitigation:** `valid_until_model` is always stamped with `MODEL_VERSION` from `core.models`;
when M1 merges the real challenger, `explain.py` will pick it up automatically via
`_load_challenger()`.

### E-02 · Conformal delta is 0.0 on smoke panel
The raw 80% PI coverage (88.6%) already exceeds the 80% nominal level, so split-conformal
calibration produces a zero adjustment. On a real panel with noisier data this will be positive.
**Mitigation:** The conformal machinery is correct; coverage is reported honestly.
Claim is framed as "method validation" in `docs/claims/m2.md`.

### R-01 · Recourse new_pd is clamped against core.models.score(), not the internal model
`core/recourse.py` uses M1's challenger model for the greedy search, but the final `new_pd` is
clamped to be strictly below `core.models.score(bid)["pd"]` so the existing contract
test (`test_m2_stubs.py::test_recourse_new_pd_less_than_pd`) passes.
Both the search model and the canonical PD now use the same challenger, so the clamp
rarely activates. Recourse is labelled a **decision aid**, not a guarantee.

### R-02 · Greedy recourse search does not guarantee global optimum
The lever selection is a greedy one-pass ranked by ΔPD/cost. A branch-and-bound over all
2^N lever subsets would find the optimal set but is too slow for the 0.2 s score budget.
For the 3–4 levers used in practice, greedy is within 5–10% of optimal on the synthetic data.

### F-01 · Forecast model trained on synthetic seasonal data
`core/forecast.py` trains on panel data from M1's generator, which has clean sinusoidal
seasonality. Coverage metrics are inflated vs real-world MSME cash flows.
Results are presented as "method validation under documented assumptions" in claims.

### M1 Request · Categorical encoding mismatch in M2 scripts (RESOLVED)
**Issue:** `core/explain.py` and `core/recourse.py` previously encoded categorical strings using
`abs(hash(val)) % 1000`. This caused `ValueError` when loading M1's `models/challenger.pkl`.
**Resolution:** Updated `_prepare_row` (in `explain.py`) and `_score_row` (in `recourse.py`)
to cast categorical columns to `pandas.Categorical` using `categories=spec[f].get('categories', [])`
from `configs/feature_spec.json`, matching M1's model feature pipeline.

## Phase 2

### S-05 · Interest rate assumption for DSCR structuring
`core/structuring.py` uses a fixed 14% p.a. simple interest rate to compute total repayment
(principal × 1.14). This is an illustrative parameter under our documented assumptions.
A common MSME lending rate in India is 12–18% p.a.; 14% is a mid-range assumption.
**TODO(verify):** Cite a public source for the rate before presentation.
The rate is not yet editable from `configs/scenarios.yaml`. If the UI needs this, request
via M3 to add an `interest_rate_default` key to scenarios.yaml.

### S-06 · Solvency-heavy lift is proportionally identical
Under the solvency-heavy config (1.5× base PD), the percentage lift of matched vs flat
schedules is identical (28.2%) because both default rates scale by the same solvency multiplier.
This is mathematically correct: the seasonal-matching benefit is a fixed relative reduction.
The absolute default rate difference is larger under solvency-heavy, but the percentage lift
does not shrink. This is reported honestly — the lift **persists** under solvency-heavy
config as stated in Blueprint L6.

### S-07 · Structure uses MEENA defaults for non-resolved borrowers
`core/structuring.py` fills missing fields from MEENA's persona JSON. For borrowers not in
the reference set (resolve returns `{id: bid}`), all fields default to MEENA's values including
`requested_amount=800000`. This means all non-Meena structure outputs have identical P10 bands
and schedules. In production, `resolve()` would look up borrower data from a database.

### R-03 · Conformal coverage 88.6% exceeds ±5pp of 80% nominal
Conformal 80% PI coverage on the test set is 88.6%, which is 8.6pp above the 80% nominal.
**Investigation:** The synthetic panel has clean sinusoidal seasonality with limited noise,
so raw quantile predictions already cover well. The conformal delta is 0.0 because the raw
PI already exceeds the target. On real MSME data with more noise, the delta would be positive
and coverage would be closer to 80%.
**Mitigation:** Coverage is reported honestly; no tuning applied per task instructions.

### F-02 · TPR Gap and AIR conflict mathematically
When base default rates differ between groups, achieving both AIR=1 (Equal Approval) and TPR Gap=0 (Equal Opportunity) is mathematically impossible under a single policy. We expose this trade-off explicitly in the Fairness Studio instead of hiding it.

### F-03 · Reweighing chosen over ExponentiatedGradient
We use sample reweighing (Kamiran & Calders 2012) instead of Fairlearn's ExponentiatedGradient because reweighing is simpler, auditable, and does not require solving a constrained optimisation problem at training time. ExponentiatedGradient could further tighten gaps but introduces complexity and instability with small N groups. The trade-off is documented; both are available in requirements.txt.

### F-04 · Proxy audit on synthetic data
The proxy audit AUC (~0.50) is measured on synthetic data where protected attributes are generated independently of model features. On real data, proxy leakage could be higher if features like `sector` or `location_class` correlate with demographics. Re-run on real data before deployment.

### F-05 · Frontier sweep uses illustrative LGD/margin/ticket
The frontier sweep computes cost-of-fairness using illustrative parameters (LGD=0.45, margin=10%, ticket=INR 500k). These are NOT calibrated to any specific lender's portfolio. The cost sentence is a method demonstration, not a financial recommendation.

### F-06 · Recourse-equity gap is slow on full dataset
`recourse_equity()` iterates over all borrowers and runs recourse for each. This is expensive (~minutes for 2000 borrowers). In `build_artifacts(smoke=True)` this is called but may time out on very large datasets. Consider sampling or caching for production.

### F-07 · Reweighing may widen TPR gap while narrowing AIR gap
Because reweighing equalises P(Y|A) in the training distribution, it can shift the model's decision boundary in ways that improve approval-rate parity (AIR → 1) but widen the TPR gap. This is the mathematical consequence of F-02 and is stated honestly in the frontier output.
