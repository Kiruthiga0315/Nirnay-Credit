## 1. Known Limitations of Current Stubs

### 1.1 recourse.py

| ID | Severity | Issue |
|---|---|---|
| R-01 | Medium | **No real model re-score.** The stub reduces PD by a fixed fraction of `stable_unit`. Real implementation must call the actual trained challenger model after each lever move and recompute all derived features with `recompute_derived()`. |
| R-02 | Medium | **No monotone-constraint enforcement.** The stub assumes monotone directions from `feature_spec.json`. The real model must be trained with LightGBM `monotone_constraints` so recourse steps always reduce PD. |
| R-03 | Low | **Recourse equity not yet measured.** Blueprint §5.4 requires comparing median cost-to-approve across groups (women-led vs others, rural vs urban). The stub does not segment by group. |
| R-04 | Low | **No feasibility interaction between levers.** Reducing `receivable_days` also changes `cash_conversion_days`. The stub calls `recompute_derived()` but does not chain lever interactions (e.g. receivable_days → cash_conversion_days → inflow_stability_cv). |
| R-05 | Low | **`valid_until_model` is meaningful only once M1 freezes MODEL_VERSION.** Until M1 trains the real model, all recourse advice carries `stub-0`. UI should show a STUB banner. |

### 1.2 structuring.py

| ID | Severity | Issue |
|---|---|---|
| S-01 | High | **No real quantile forecast.** P10 band is derived from a fixed seasonal multiplier × UPI inflow. Real implementation (M2 later) must fit a quantile GBM or use split-conformal calibration. |
| S-02 | Medium | **Tenor is hard-coded to 12 months.** Contract `StructureResult.tenor_months` should reflect the actual loan tenor from `requested_amount` / monthly instalment. Requires borrower-specific tenor optimisation. |
| S-03 | Low | **Default rate simulation is a stub function, not a simulation.** Real implementation should run the stress engine on the proposed schedule. |
| S-04 | Low | **Schedule ceiling truncation.** Repayment schedule uses `math.floor(x / target_dscr)` rather than `round()` to guarantee `schedule[t] <= p10_band[t] / target_dscr` strictly holds for all months without fractional penny violations. |

### 1.3 fairness.py

| ID | Severity | Issue |
|---|---|---|
| F-01 | High | **Group metrics do not come from real model predictions.** The stub uses `stable_unit` to generate group rates. Real implementation must compute approval rates and TPR from actual model scores on the generated borrower population. |
| F-02 | Medium | **Intersectional CI uses a binomial approximation.** For small groups (< 500 members), Wilson intervals are preferred. The `small_n` flag is set but the stub uses a normal approximation. |
| F-03 | Medium | **Proxy audit not yet implemented.** Blueprint §5.6 requires training a classifier to predict protected attributes from neutral features and reporting top proxies. |
| F-04 | Low | **Recourse-cost equity gap not yet computed.** The fairness report should include the median cost-to-approval gap across groups. |

### 1.4 optimizer.py

| ID | Severity | Issue |
|---|---|---|
| O-01 | High | **LP relaxation is greedy, not true LP.** Real implementation should use `scipy.optimize.linprog` or PuLP with the full constraint matrix. The greedy approach can miss the optimum when constraints bind simultaneously. |
| O-02 | Medium | **Sector cap constraint is not yet enforced.** `sector_cap` key in `policy_params` is accepted but not used because sector membership is not in the stub borrower features. |
| O-03 | Low | **EL = PD × LGD × ticket uses a fixed LGD = 0.45.** LGD should come from `requested_amount`, collateral, and sector. M1 owns the LGD stub; coordinate via M3 artifacts. |
| O-04 | Low | **`approved_ids` may change across Python versions** if `sorted()` order is not stable for equal-net borrowers. Add a tiebreak by `bid` to guarantee determinism. |

### 1.5 features.py

| ID | Severity | Issue |
|---|---|---|
| FE-01 | Low | **`inflow_stability_cv` uses population std-dev** (`pstdev`). When the real monthly inflow series is available, consider sample std-dev (`stdev`) and note the convention in claims. |
| FE-02 | Low | **`revenue_growth_3m` uses `revenues[-4]` as the 3-month-ago base.** If the list is shorter than 4 entries, it falls back to `revenues[0]`, which may span a different window. Document the fallback. |
| FE-03 | Low | **`load_spec()` is cached with `lru_cache(maxsize=1)`.** Tests that mutate the spec (e.g. fixture injection) must call `load_spec.cache_clear()` before and after. |

## 2. Contract Improvement Proposals

> These are proposals only. Do NOT edit `core/contracts.py` without the `contract-change`
> process (all four members' approval). These proposals should be raised as a PR comment.

### 2.1 RecourseResult — add `recourse_equity_gap`

```python
# Proposed additional key (optional, backward-compatible if policy allows it)
"recourse_equity_gap": dict[str, float]
# e.g. {"women_led": 1.4, "rural": 1.6}
# ratio of median cost-to-approve for the group vs the reference group
```

**Rationale:** Blueprint §5.4 explicitly requires recourse-equity measurement. The UI
Fairness Studio page needs this value to render the "price of fairness" panel. Without
it, M4 must make a separate `fairness_report()` call and join results client-side, which
violates the "UI reads only artifacts" rule.

### 2.2 StructureResult — add `tenor_months_actual` and `conformal_coverage`

```python
"tenor_months_actual": int   # borrower-specific, may differ from 12
"conformal_coverage": float  # empirical coverage of the p10_band (0-1)
```

**Rationale:** The current contract hard-codes `tenor_months` but the real structuring
engine may output a borrower-specific tenor. `conformal_coverage` lets the UI show
"P10 band was correct in X% of backtested months", supporting the Blueprint §5.5
requirement for defensible intervals.

### 2.3 FairnessReport — add `recourse_cost_gap`

```python
"recourse_cost_gap": dict[str, float]
# e.g. {"women_led": 1.3, "rural": 1.5}
# median total recourse cost for the group / median for the reference group
```

**Rationale:** Fairness must be measured not only on approval rates but on the cost of
reaching approval. Without this key the UI cannot render the recourse-equity panel
described in Blueprint §5.6.

### 2.4 OptimizeResult — add `sector_breakdown` and `n_approved`

```python
"sector_breakdown": dict[str, int]   # approved count per sector
"n_approved": int                    # total approved count
```

**Rationale:** The Portfolio Command Center (Page 1) needs a sector-breakdown bar chart.
Currently M4 must compute this from `approved_ids` by joining with the borrower
population, which requires loading `data/borrowers.parquet` in the UI — violating
"UI reads only artifacts".

### 2.5 Borrower type — consider a `BorrowerProfile` TypedDict

The current `Borrower = dict[str, Any] | str` is untyped. A `BorrowerProfile` TypedDict
listing all 24 features with their types would:
- Enable static analysis to catch missing fields early.
- Let `validate_spec()` cross-check field names against the spec at import time.
- Give M4's UI autocomplete when building slider inputs.

This is a larger change requiring all four members' sign-off.
