## New (Phase 1, m4/p1-page2-cockpit)

### KI-M4-001: What-if slider re-score does not recompute derived features for non-Meena borrowers
- **Symptom**: For borrowers other than Meena (`MSME-00001`), `b_base` is synthesised from
  Meena's fixture merged with `{id: bid}`. This means `monthly_inflow` and `monthly_revenue`
  list fields used by `core.features.recompute_derived` are not present, so
  `inflow_stability_cv` and `revenue_growth_3m` are not recomputed after slider changes.
- **Impact**: What-if PD is correct for the four offered levers; derived-feature recompute is
  a no-op for non-Meena borrowers. Low severity for demo.
- **Fix path**: M1 or M3 to expose a `generate_borrower_dict(bid)` helper that returns the
  full feature dict for any of the 20 test borrowers; M4 can then call it instead of the
  Meena-merge fallback.
- **Request to M3**: Please expose a `core.generator.get_borrower(bid)` (or similar) that
  returns the full feature dict for MSME-00001 to MSME-00020.

### KI-M4-002: `core.structure` response is cached by `(bid, target_dscr)` key
- **Symptom**: When the DSCR slider moves, Streamlit re-runs the page with the new `target_dscr`
  value and `_cached_structure(bid, target_dscr)` is called. `st.cache_data` caches by all
  arguments, so every unique `(bid, dscr)` combination is stored in memory. With 20 borrowers
  and ~21 slider positions the cache could hold up to 420 entries.
- **Impact**: Memory pressure on resource-limited deployments (e.g., Streamlit Community Cloud
  free tier). Negligible for a demo, significant for production.
- **Fix path**: Add `max_entries=100` to the `_cached_structure` `@st.cache_data` decorator,
  or switch to `st.session_state` memoisation keyed on the current borrower only.

## Phase 3 (m4/p3-journey-story)

### KI-M4-003: Journey simulator PD may not monotonically decrease for all borrowers with multiple levers
- **Symptom**: When multiple levers are applied simultaneously with an S-curve, the intermediate PD
  from `core.score` may not strictly decrease if the model has non-linear interactions between features.
  The test only validates monotonicity for Meena's single-lever (receivable_days) case with a mock scorer.
- **Impact**: Low severity for demo; the curve always moves in the right direction over 6 months.
- **Fix path**: When M1's real model is finalised, run a validation script against all 20 borrowers
  and document any non-monotone cases in this file.

### KI-M4-004: Story Mode does not auto-navigate pages (requires manual navigation)
- **Symptom**: The Story Mode "Play Demo" control shows callouts but cannot programmatically switch
  Streamlit pages. The presenter must click the page in the sidebar after reading each callout.
- **Impact**: Minor friction during live demo. Story Mode still protects against shaky networks
  and nervous presenters by providing scripted callout text.
- **Fix path**: Streamlit 1.35+ introduces `st.switch_page()`. Upgrade when available on deployment
  target and wire each slide's `page_target` to `st.switch_page(page_target)`.

### KI-M4-005: Policy optimizer `sector_cap` slider wired but `core.optimize` does not enforce it
- **Symptom**: `core.optimizer.py` (M2 stub) does not use the `sector_cap` parameter.
  The slider is displayed and the param is passed to `core.optimize`, but has no effect.
- **Impact**: None for demo; the fairness-gap and price-of-inclusion numbers are still valid.
- **Fix path**: M2 to add sector-cap enforcement to `core/optimizer.py`.
  Request filed: see docs/known_issues/m2.md (request from M4).
